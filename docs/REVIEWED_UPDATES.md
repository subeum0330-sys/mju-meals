# 매주 인스타 식단을 확인해 업데이트하기

현재는 **Codex가 브라우저로 식단 사진을 확인해서 등록하는 방식**을 사용합니다. Meta 개발자 등록이나 별도 OpenAI API 키가 필요하지 않습니다. 인스타그램이 로그인이나 접근 확인을 요구하면 사용자 조치가 필요할 수 있습니다.

## 주 1회 확인 예약

이 프로젝트의 로컬 대화에 **매주 월요일 오전 9시(Asia/Seoul)** 실행하는 예약을 등록했습니다. 첫 예정일은 2026년 10월 12일입니다. 저장소를 복사하거나 내려받는 것만으로 다른 컴퓨터에 예약이 만들어지지는 않습니다.

예약이 실행되면 담당 에이전트가 `mju_lounge`, `mjhs_yongin`, `mj_bangmok_foodist`, `mj_bokji_foodist`의 공개 게시물을 열어 이번 주와 미리 게시된 다음 주의 날짜·메뉴를 확인합니다. 흐린 글씨나 빠진 날짜는 추측해서 채우지 않습니다. 확인한 새 자료 또는 수정 사항만 등록하며, 새 게시물이 없으면 이전 메뉴의 날짜를 바꾸지 않습니다.

확인된 자료가 저장소에 반영되면 GitHub가 앱용 식단을 게시합니다. 앱은 실행·다시 활성화·새로고침할 때 등록된 식단을 받아옵니다. 주 1회 검사 이후 늦게 올라온 식단은 다음 예약 전까지 자동으로 재확인하지 않습니다. 필요하면 이 대화에서 추가 확인을 요청할 수 있습니다.

**예약 시간에 Mac과 Codex 앱이 켜져 있어야 합니다.** 프로젝트 파일, 브라우저 접근, GitHub 연결과 사용 한도도 실행 가능해야 합니다. 예약 등록은 첫 무인 실행의 성공을 뜻하지 않습니다. 로그인·확인 창·접근 제한이나 게시 실패가 발생하면 이 대화에 알려드립니다. 새 자료 반영 완료나 필요한 조치만 알리고, 달라진 내용이 없으면 조용히 종료합니다. [예약 실행 조건](https://learn.chatgpt.com/docs/automations?surface=app)

직접 식단 사진과 게시물 링크를 이 대화에 보내 추가 반영을 요청할 수도 있습니다. 이 경우에도 식당 이름과 날짜가 보여야 합니다.

## 처음 한 번 준비할 것

- 저장소의 Settings → Pages → Source를 **GitHub Actions**로 설정합니다.
- `Publish reviewed menus` 작업이 성공하면 [식단 게시 상태](https://subeum0330-sys.github.io/mju-meals/)와 [앱용 식단 파일](https://subeum0330-sys.github.io/mju-meals/meals.json)을 확인합니다.
- 앱의 공개 주소를 설정하고 한 번 다시 빌드합니다. 이후 식단만 바꿀 때는 앱을 다시 설치할 필요가 없습니다.

```sh
python3 scripts/configure_meal_feed.py https://subeum0330-sys.github.io/mju-meals/meals.json
```

아이폰에 처음 설치하려면 Xcode와 앱 서명 설정이 별도로 필요합니다. Mac 미리보기는 아이폰 설치 파일이 아닙니다.

## 자료를 반영하는 에이전트용 절차

1. 식당 계정, 게시물 원문, 실제 인쇄 날짜·요일, 메뉴·가격·휴무를 대조합니다. 게시된 사실만 기록합니다.
2. `Sources/MealCore/Resources/instagram-reviewed.json`에 해당 식당·해당 주를 추가하거나 수정합니다. 새 주를 추가할 때 다른 주를 지우지 않습니다. 동일 식당·동일 주 레코드는 중복 추가하지 않습니다.
3. `verifiedAt`에는 실제 대조 시각을 씁니다. 재배포할 때 기존 기록의 확인 시각을 현재 시각으로 바꾸지 않습니다. `processingMethod`는 `manual`이거나 생략합니다. 사진에서 확인하지 못한 운영시간·가격을 이전 주에서 복사하지 않습니다.
4. 아래 오프라인 검사를 통과한 뒤 검수 자료를 저장소 `main`에 반영합니다. 테스트 픽스처는 게시하지 않습니다.
5. `Publish reviewed menus` 성공, 실제 공개 JSON의 내용, 앱에서 해당 주 로딩을 확인합니다. 실패하면 성공했다고 안내하지 않습니다.

```sh
python3 -m unittest discover -s backend/tests -v
python3 -m backend.publish_reviewed --output-dir _site
```

게시기는 모든 식당·주차·출처·메뉴를 검증하고 2MiB를 넘으면 게시를 중단합니다. 알 수 없는 필드와 자동 수집 기록은 거부합니다. 공개 결과는 `meals.json`, `status.json`, `index.html`입니다. 메뉴 사진 원본이나 계정 인증 정보는 게시하지 않습니다.

공개 페이지의 게시 시각은 서버 반영 시각이며, 각 식단의 확인 시각과 다릅니다. 새 자료가 없으면 미등록으로 표시하고, 이전 주 메뉴의 날짜를 이번 주로 바꾸지 않습니다.

## 나중에 인스타 공식 API 수집으로 전환할 때

지금은 저장소 변수 `MEAL_UPDATE_MODE`가 없거나 `instagram`이 아니면 사진 확인본 게시 방식이 동작합니다. 기존 인스타 수집 작업은 이 모드에서 API를 호출하지 않습니다.

공식 API 수집으로 전환하기로 결정한 뒤에만 [선택 사항인 API 수집 설정](AUTOMATIC_UPDATES.md)을 진행합니다. `MEAL_UPDATE_MODE=instagram`을 설정하면 확인본 게시 작업은 중단되므로, 실제 계정 설정과 접근 테스트를 준비한 후 변경해야 합니다.
